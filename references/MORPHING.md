# Shape and layout morphing implementation

## Tier A: parametric morphs (MVP)

Represent `RoundedRect { rect, corners: [radius; 4] }`. Animate center/width/height separately or via a geometric state interpolator, and interpolate corner radii using a normalized morph parameter. Keep widths and heights strictly positive; clamp radii to remain geometrically valid (`rx`/`ry` edge sums must fit). Decide whether parent layout is static or animated; do not accidentally double-transform the same geometry.

## Tier B: compatible contours

Use a shape `Contour { closed: bool, segments: Vec<CubicBezier> }`. Before interpolation:

1. Convert both shapes to a consistent coordinate system (typically a unit box).
2. Confirm both are closed/open as required; determine winding and reverse if needed.
3. Identify salient landmarks (corners, lobes, semantic anchors) and align starting points.
4. Split curve segments or resample by arc length to form compatible correspondence.
5. Compute a matching that minimizes twist and drift (e.g. cyclic offset search under constraints).
6. Cache alignment and mapping; ensure morphing does not self-intersect unexpectedly.
7. Interpolate corresponding control points, then transform to output bounds.
8. Provide fallback crossfade if shapes or topology cannot be matched safely.

Linear path control-point interpolation: `B_i(p) = (1-p)*A_i + p*C_i`. If `p` is generated by an underdamped spring, **clamp to [0,1] for shapes that don't support extrapolation** or prevent geometry-inverting overshoot by using a critical-damped morph parameter with expressive springs on other presentation properties.

Points sampled uniformly by array index are not automatically meaningful correspondence. Poor winding/alignment produces twisting or collapsing geometry.

## Tier C: topology changes (future)

Holes, multi-contour objects, or one shape splitting into two are not covered by simple contour interpolation. Possible future methods include signed-distance-field blending, mesh deformation, or semantic split choreography. Each has quality/performance tradeoffs. Start with a clear graceful fallback.

## Rendering integration

- For rounded rectangles: prefer analytic shader or clip geometry rather than retessellating polygons on each frame.
- For general contours: tessellate or use a path renderer; cache correspondence and reusable allocation, not invalid geometry.
- Morph paths and shared-element transformations are independent systems.
- Use consistent clipping and hit-test policy, and a defined z-order during shared transitions.
- Text/icons should generally be crossfaded/reflowed, not geometrically stretched into illegibility.

## Recommended demos

1. Square to rounded rectangle to pill.
2. Pill button to sheet with coherent content reveal.
3. Compatible six-point rounded polygon to circle.
4. Bad correspondence example detected and handled by a fallback.
